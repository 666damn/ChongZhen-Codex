# 《历史模拟器：崇祯》Codex 单文件安装器设计

## 目标

交付一个 Windows x64 单文件图形化安装器 `ChongZhenCodexInstaller.exe`，把当前已经验证可运行的 Codex 桥接、自动监听和服务器地区分流方案移植到其他电脑。

目标电脑必须已经安装、运行并登录过 Codex CLI。安装器不迁移账号，不内置 Codex 可执行文件，不要求用户提供 OpenAI Platform API Key，也不写死 Codex 模型。

安装器提供两种模式：

1. **仅 Codex 桥接**：安装本机桥接和自动监听，并在游戏 BYOK 配置中增加“本机 Codex”；不替换游戏 EXE、ASAR 或 DLL。
2. **Codex 桥接 + 全球分流**：在前一模式基础上，采用当前机器已验证的 ASAR 与 `version.dll` 完整性兼容方式安装地区分流补丁；游戏 EXE 始终保持原字节。

## 固定约束

- 最终桌面只交付一个 EXE；开发材料统一放在仓库根目录。
- 运行文件统一安装到 `%LOCALAPPDATA%\ChongZhenCodexBridge`。
- 游戏可能位于任意本机固定磁盘，路径不能写死。
- 桥接只监听 `127.0.0.1`，不向局域网或互联网开放端口。
- 使用目标电脑当前 Codex 登录账号和当前生效模型；安装器不包含当前开发电脑的账号、模型、配置、会话或本地状态。
- 账号切换不建立隔离数据库；游戏产生的同一逻辑会话继续使用共享的本地会话映射。
- 游戏正常启动后桥接自动启动，用户不需要手动运行第二个程序。
- 不修改 `ChongZhenSimulator.exe`。

## 方案选择

采用 .NET 8 自包含 WinForms 单文件程序作为安装器和后台管理入口。安装器把干净的桥接程序、便携 Node.js 24 x64、受支持版本的补丁载荷和资源嵌入单个 EXE，安装时解压到当前用户的 LocalAppData。

不采用 IExpress/PowerShell 自解压包，因为它依赖目标机脚本环境且错误恢复较弱。不采用 Node SEA 作为安装器，因为图形界面、提权、原子文件替换和 Windows 自启动管理会更复杂。

目标机无需另装 Node.js。目标机必须存在本机 Codex CLI；桥接只发现并启动该 Codex CLI，不使用安装器内置的 Codex 版本。

## 组件

### 安装器与管理器

同一个 EXE 支持以下入口：

- 首次安装
- 查看状态
- 修复安装
- 切换安装模式
- 恢复游戏原版文件
- 卸载桥接
- 后台监听模式 `--watch`

首次安装后，EXE 自身的一份副本安装到 LocalAppData。HKCU 自启动项调用该副本的 `--watch` 模式，不需要管理员权限。若全球分流模式的 Steam 库目录需要管理员写权限，只针对游戏文件安装阶段请求 UAC 提权。

### Codex 桥接

桥接保留现有 OpenAI Chat Completions 兼容 HTTP 接口，把游戏请求转换为 Codex app-server 的 thread/turn 调用。

Codex 可执行文件发现顺序为：

1. 显式的 `CHONGZHEN_CODEX_PATH`，仅当用户主动设置且文件有效时使用。
2. 当前 `PATH` 中的 `codex.exe`。
3. `%LOCALAPPDATA%\OpenAI\Codex\bin\*\codex.exe` 中最新的有效安装。

桥接启动 `codex app-server --listen stdio://`。每次开始请求时通过 `config/read` 读取当前生效模型；模型值只在内存中用于当前请求，不写入桥接配置或数据库。桥接通过 `account/read` 仅判断是否已登录，立即丢弃返回的账号对象。

Codex thread 使用只读沙箱、`approvalPolicy: never` 和独立工作目录。游戏提供的工具定义只作为结构化输出约束返回给游戏，不注册为 Codex 本机工具。

### 自动监听器

后台监听器每两秒检查 `ChongZhenSimulator.exe`：

- 检测到游戏后启动桥接。
- 桥接异常退出且游戏仍在运行时自动重启。
- 游戏退出后保留六十秒，随后关闭桥接。
- 监听器与桥接均以隐藏窗口运行。

### 游戏 BYOK 配置

安装器通过一次由 Steam 启动的临时调试会话访问游戏 localStorage，在内存中合并 `local_codex` provider 和 strategy，并把它设为当前策略。

五种游戏模型角色全部指向本机桥接。各角色在请求中的逻辑名称仍保留，实际 Codex 模型由桥接每次从本机 Codex 配置读取。

配置器不得把完整 localStorage 或完整 BYOK 配置写入磁盘，不得保存其他 provider 的 API Key。卸载时只删除安装器自己创建的 `local_codex` provider/strategy；其他项目原样保留。若卸载时 `local_codex` 仍是活动策略，则选择现存的第一个有效非本地策略；没有其他策略时清空活动选择。

## 游戏路径自动定位

Steam App ID 固定为 `4304230`。定位顺序如下：

1. 验证安装器上次缓存的游戏目录及 EXE 身份。
2. 从 Steam 注册表获取主目录。
3. 解析 `steamapps\libraryfolders.vdf` 中的全部库目录。
4. 在每个库中读取 `appmanifest_4304230.acf`，使用其 `installdir` 组合游戏目录。
5. 若 Steam 配置缺失或损坏，检查常见 Steam 根目录和所有固定磁盘上的 `steamapps` 目录。
6. 最后才执行有边界的固定磁盘扫描，查找 `appmanifest_4304230.acf` 或 `ChongZhenSimulator.exe`，并跳过无权限、系统和回收站目录。

候选目录必须同时包含：

- `ChongZhenSimulator.exe`
- `resources\app.asar`

全新 Steam 安装尚未注入代理时可以没有 `version.dll`；若它已存在，安装器会把它视为待验证和备份的现有文件。

存在多个候选时优先使用 Steam 当前登记的有效安装；仍不唯一时显示候选选择窗口。缓存失效或游戏被 Steam 移动后自动重新定位。

## 地区分流

游戏原始地区语义保持不变，只改原本锁定的其他国家：

| `country_code` | 原始结果 | 全球分流结果 |
| --- | --- | --- |
| 空值或缺失 | 国内服 | 国内服 |
| `CN` | 国内服 | 国内服 |
| `HK` / `MO` / `AU` | 国际服 | 国际服 |
| 其他非空国家代码 | Locked | 国际服 |

全球分流模式使用这台电脑按当前方式生成的、受支持客户端版本完整验证补丁载荷。目标电脑不重新反编译或打包，且原始游戏哈希不匹配时拒绝安装。补丁载荷只包含已确认的 Codex 请求适配和地区函数更改，不包含当前开发电脑的密钥、路径或状态。构建时生成一个新的发布专用回环桥接识别码；它不是 ChatGPT、Codex 或 API 登录凭据。

`version.dll` 只负责转发系统 Version API，并在进程内把 Electron 预期的 ASAR 完整性哈希适配为已安装补丁的哈希。它不代理网络，不保存数据，也不修改 EXE 磁盘内容。

## 文件安全、备份与恢复

全球分流模式安装前必须确认游戏进程已经退出，并验证受支持版本的 EXE、原始 ASAR，以及存在时的原 `version.dll` 哈希。

安装流程为：

1. 把原始 `app.asar` 和存在的 `version.dll` 复制到 LocalAppData 的版本化备份目录；不存在的文件记录为“原先不存在”。
2. 验证备份长度与 SHA-256 和源文件一致。
3. 在游戏文件所在卷创建补丁临时文件并验证嵌入清单中的长度与 SHA-256。
4. 使用同卷原子替换安装补丁。
5. 再次验证已安装文件和游戏 EXE 哈希。
6. 任一步失败时恢复已验证备份，并报告具体阶段。

修复或卸载只在当前文件等于安装器已知的原始哈希或补丁哈希时操作。遇到 Steam 更新、用户手动修改或未知文件时停止覆盖，保留备份并提示使用 Steam 文件验证。

“仅 Codex 桥接”模式不替换 ASAR 或 DLL。由全球分流模式切回仅桥接模式时，先恢复安装前的原始文件并验证哈希。

## 本机数据边界

安装器和桥接器禁止：

- 直接读取、枚举、复制、压缩、导出或备份现有 `.codex` 数据目录。
- 保存或记录 ChatGPT/Codex access token、refresh token、Cookie、密码、邮箱、账号 ID、套餐信息或账号对象。
- 保存本机现有 Codex 配置文件、模型列表、历史 thread 内容或历史聊天记录。
- 把开发电脑的 `state.db`、日志、桥接 token、游戏备份、localStorage 备份或用户配置打进发布 EXE。
- 在日志中记录完整游戏提示词、完整模型回复、BYOK 配置或任何 API Key。

允许且必需的数据访问为：

- 通过 Codex app-server 临时判断登录是否存在。
- 通过 `config/read` 临时读取当前模型名。
- 通过 app-server 新建、恢复并调用本安装产生的游戏 thread。

桥接自己的 LocalAppData 目录只保存：

- 构建时新生成、仅用于 `127.0.0.1` 请求识别的发布桥接码；不得复用开发电脑现有 bridge token，且该值不能用于登录任何账号。
- 游戏路径、安装模式、版本和文件哈希清单。
- 游戏文件备份。
- 本安装产生的 `conversation key -> Codex thread ID` 映射和规范化消息哈希。
- 不含提示正文、回复正文和身份资料的运行状态日志。

Codex CLI 自身会按其正常机制保存本安装新建的 thread；安装器不直接访问其存储。上下文持久化依赖 thread ID 映射，因此删除全部桥接状态时会失去游戏与既有 Codex thread 的关联。

## 错误处理

- 未找到游戏：显示已搜索的 Steam 库和“重新扫描”按钮，不写入任何游戏文件。
- 未找到 Codex：给出目标机需要先安装并运行 Codex CLI 的提示。
- Codex 未登录：安装桥接可以完成，但状态页显示未登录；游戏请求返回本机认证错误，不回退到 Platform API Key。
- 端口被占用：确认占用进程是否是已安装桥接；不是则停止启动并给出诊断。
- 游戏正在运行：全局补丁、修复和恢复操作被禁止；只允许查看状态。
- 文件版本不受支持：仅 Codex 模式仍可安装；全球分流模式不覆盖文件。
- 配置临时会话失败：不保存完整 localStorage，保留其他 provider，并允许重试。

## 测试与验收

### 单元测试

- Steam 注册表、VDF、manifest、缓存和全盘兜底定位。
- 多候选、无权限目录、移动安装和损坏 manifest。
- 地区映射：空值、`CN`、`HK`、`MO`、`AU`、`US`、`DE` 和未知非空代码。
- BYOK 合并和删除只影响 `local_codex`，测试配置中放置诱饵 API Key，断言任何备份、日志和发布文件均不包含它。
- 安装状态机、失败回滚、哈希不匹配和幂等修复。
- Codex 路径发现、当前模型读取、不落盘账号对象。

### 集成测试

- 在临时 Steam 目录和不同模拟盘符安装、切换模式、修复和卸载。
- 无系统 Node.js 环境下使用内置 Node 运行桥接。
- 使用假的 app-server 验证登录、模型变化、thread 持久化、并发和取消。
- 扫描发布 EXE 和解压载荷，确认不含开发电脑路径、邮箱、token、state 数据库、日志和用户配置。
- 验证全球分流安装前后游戏 EXE SHA-256 完全一致。
- 验证失败注入后的原始 ASAR 和 DLL 与备份逐字节一致。

### 当前机器验收

- 自动定位任意本机固定磁盘 Steam 库中的《历史模拟器：崇祯》。
- 安装后通过 Steam 正常启动游戏。
- 游戏启动两秒内桥接自动运行，退出六十秒后桥接关闭。
- 五个游戏模型角色均走本机 Codex，不调用游戏普通模型 token。
- 改变本机 Codex 默认模型后，下一次游戏请求使用新模型，无需重装。
- 切换 Codex 登录账号后继续共享的游戏会话映射，桥接数据库不出现账号资料。
- 全球分流表中所有国家测试通过。
- 恢复原版后备份文件哈希完全一致。

## 发布产物

发布目录只包含：

```text
dist\ChongZhenCodexInstaller.exe
```

单文件 EXE 包含安装所需的干净运行时和补丁载荷。发布构建生成一份内部载荷清单，记录每个嵌入文件的相对路径、长度和 SHA-256；安装器在解压和安装前后都验证该清单。
